## 🗃️ 完整建表SQL

### 1. 用户表（users）

```sql
DROP TABLE IF EXISTS `users`;
CREATE TABLE `users` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID, 主键',
    `username` VARCHAR(50) NOT NULL COMMENT '用户名, 唯一',
    `password` VARCHAR(255) NOT NULL COMMENT '密码 (Bcrypt加密)',
    `email` VARCHAR(100) NOT NULL COMMENT '邮箱, 唯一',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '账户创建时间',
    `last_login_time` DATETIME DEFAULT NULL COMMENT '最后登录时间',
    `role` VARCHAR(50) NOT NULL DEFAULT 'ROLE_USER' COMMENT '用户角色',
    `avatar_url` VARCHAR(255) DEFAULT '/default-avatar.png' COMMENT '头像URL',
    `gender` TINYINT DEFAULT 0 COMMENT '性别：0未知,1男,2女',
    `bio` VARCHAR(500) DEFAULT '' COMMENT '个人简介',
    `location` VARCHAR(100) DEFAULT '' COMMENT '所在地',
    `points` INT DEFAULT 0 COMMENT '积分',
    `level` INT DEFAULT 1 COMMENT '用户等级',
    `is_banned` TINYINT(1) DEFAULT 0 COMMENT '是否被封禁',
    `ban_reason` VARCHAR(255) DEFAULT NULL COMMENT '封禁原因',
    `ban_until` DATETIME DEFAULT NULL COMMENT '封禁截止时间',
    `is_deleted` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '软删除标记：0正常,1已注销',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_username` (`username`) COMMENT '唯一索引用户名',
    UNIQUE KEY `uk_email` (`email`) COMMENT '唯一索引邮箱',
    KEY `idx_create_time` (`create_time`) COMMENT '普通索引创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户表';
```

**字段说明：**
- `avatar_url`: 头像URL，默认使用系统头像
- `gender`: 0未知/1男/2女，使用TINYINT节省空间
- `points/level`: 为后续用户等级体系预留
- `is_banned`: 封禁标记，配合 `ban_reason` 和 `ban_until` 使用
- `is_deleted`: 软删除，用户注销后标记为1，前端显示"用户已注销"，数据仍保留
- `role`: 简化版只有USER和ADMIN，复杂权限可扩展

> 📝 **与旧版设计的变更**：
> - 新增 `is_deleted` 字段（支持用户注销软删除）
> - `email` 保持 `NOT NULL`（注册必填）

### 2. 帖子表（posts）

```sql
DROP TABLE IF EXISTS `posts`;
CREATE TABLE `posts` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '帖子主键ID',
    `user_id` BIGINT NOT NULL COMMENT '作者的用户ID',
    `title` VARCHAR(255) NOT NULL COMMENT '帖子标题',
    `content` TEXT NOT NULL COMMENT '帖子内容',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `category_id` BIGINT NOT NULL COMMENT '分区ID',
    `category_name` VARCHAR(50) NOT NULL COMMENT '分区名（冗余字段，避免JOIN查询）',
    `cover_image` VARCHAR(255) DEFAULT NULL COMMENT '封面图URL',
    `view_count` INT DEFAULT 0 COMMENT '浏览量',
    `like_count` INT DEFAULT 0 COMMENT '点赞数',
    `collect_count` INT DEFAULT 0 COMMENT '收藏数',
    `comment_count` INT DEFAULT 0 COMMENT '评论数',
    `status` TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0草稿,1待审核,2已发布,3已拒绝,4已删除',
    `is_pinned` TINYINT(1) DEFAULT 0 COMMENT '是否置顶',
    `is_essence` TINYINT(1) DEFAULT 0 COMMENT '是否加精',
    `ip_address` VARCHAR(50) DEFAULT NULL COMMENT '发布者IP',
    `summary` VARCHAR(305) NOT NULL COMMENT '帖子简介，用于列表预览展示',
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`) COMMENT '为作者ID创建索引以优化查询',
    KEY `idx_category_id` (`category_id`),
    KEY `idx_status` (`status`),
    KEY `idx_create_time` (`create_time`),
    KEY `idx_update_time` (`update_time`),
    KEY `idx_view_count` (`view_count`),
    KEY `idx_like_count` (`like_count`),
    KEY `idx_hot` (`like_count`, `comment_count`, `view_count`) COMMENT '热度综合索引'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='帖子表';
```

**重要索引说明：**
- `idx_hot`: 组合索引，用于热门排序查询
- `idx_update_time`: 用于"最新"排序
- `idx_category_id`: 用于按分区查询

**状态说明：**
- 0: 草稿（用户保存但未发布）
- 1: 待审核（需要管理员审核的场景）
- 2: 已发布（正常展示）
- 3: 已拒绝（审核未通过）
- 4: 已删除（软删除）

> 📝 **与旧版设计的变更**：
> - `category_id` 从 `DEFAULT NULL` 改为 `NOT NULL`（发帖必须选分区）
> - 新增 `category_name` 冗余字段（反范式设计，列表页避免 JOIN categories 表）
> - 新增 `summary` 字段（帖子摘要，列表页预览用）
> - `content` 从 `LONGTEXT` 改为 `TEXT`（64KB 足够论坛帖子）
> - `status` 默认值从 1(待审核) 改为 0(草稿)
> - **去掉了外键约束**（`fk_posts_users`、`fk_posts_categories`），改为应用层控制，符合互联网项目规范
> - 保留了 `idx_create_time`、`idx_update_time` 索引（等待查询场景需要单独索引）

### 3. 评论表（comments）

```sql
DROP TABLE IF EXISTS `comments`;
CREATE TABLE `comments` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '评论主键ID',
    `post_id` BIGINT NOT NULL COMMENT '所属帖子ID',
    `user_id` BIGINT NOT NULL COMMENT '评论者的用户ID',
    `content` TEXT NOT NULL COMMENT '评论内容',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '评论创建时间',
    `ip_address` VARCHAR(45) DEFAULT NULL COMMENT '评论时用户ip',
    `parent_id` BIGINT DEFAULT NULL COMMENT '父评论ID',
    `reply_to_user_id` BIGINT DEFAULT NULL COMMENT '回复给谁',
    `like_count` INT DEFAULT 0 COMMENT '点赞数',
    `is_deleted` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`),
    KEY `idx_post_id` (`post_id`) COMMENT '为加速查询帖子下的所有评论的索引',
    KEY `idx_user_id` (`user_id`) COMMENT '为加速查询用户的评论的索引',
    KEY `idx_comments_parent` (`parent_id`) COMMENT '评论的父id',
    KEY `idx_post_time` (`post_id`, `create_time`) COMMENT '评论分页用，按帖子分时间查询'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='评论表';
```

**楼中楼设计：**
```
一级评论：parent_id = NULL
二级评论：parent_id = 一级评论ID
reply_to_user_id: @某个用户时使用
```
**评论结构说明（B站式两层扁平化）**：
  - 楼主评论：parent_id = NULL
  - 所有回复：parent_id = 楼主评论ID（平行结构）
  - 显示方式：通过 reply_to_user_id 显示"回复@某人"
  - 删除策略：is_deleted 软删除标记

> 📝 **与旧版设计的变更**：
> - **去掉了所有外键约束**（`fk_comments_posts`、`fk_comments_users`、`fk_comments_parent`、`fk_comments_reply_to`），改为应用层控制
> - `ip_address` 从 `VARCHAR(50)` 改为 `VARCHAR(45)`（IPv6 最长45字符，更精确）
> - 原 `idx_parent_id` 改名为 `idx_comments_parent`
> - 新增组合索引 `idx_post_time(post_id, create_time)`，用于评论分页查询优化
> - 去掉了原单列 `idx_create_time` 索引（已被 `idx_post_time` 覆盖主要场景）
> - 表级注释缺失（数据库中无 COMMENT，可后续补充）

### 5. 点赞表（likes）—— 统一设计 + target_type 方案

```sql
DROP TABLE IF EXISTS `likes`;
CREATE TABLE `likes` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '点赞ID',
    `user_id` BIGINT NOT NULL COMMENT '点赞用户ID',
    `target_id` BIGINT NOT NULL COMMENT '目标ID(帖子/评论)',
    `target_type` TINYINT NOT NULL COMMENT '类型：1帖子，2评论',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '点赞时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_target` (`user_id`, `target_id`, `target_type`) COMMENT '防止重复点赞,唯一键',
    KEY `idx_target` (`target_id`, `target_type`),
    -- 用户注销即销毁关系
    CONSTRAINT `fk_likes_users` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='点赞表';
```

**设计决策说明：**

> 采用**统一 likes 表 + target_type 字段**方案（而非分开 `post_likes`、`comment_likes`），理由：
> - 一张表维护简单，扩展新点赞对象只需新增 type 值
> - 唯一索引 `uk_user_target(user_id, target_id, target_type)` 足以防重复
> - 通过 `idx_target(target_id, target_type)` 组合索引保证查询性能
> - 级联删除：用户删除时自动删除点赞记录

### 8. 帖子图片表（post_images）🆕

```sql
DROP TABLE IF EXISTS `post_images`;
CREATE TABLE `post_images` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '贴图关系id',
    `post_id` BIGINT DEFAULT NULL COMMENT '所属帖子-未绑定时为空',
    `image_url` VARCHAR(512) NOT NULL COMMENT '图片访问url',
    `object_name` VARCHAR(512) NOT NULL COMMENT 'MinIO中的对象名',
    `status` TINYINT NOT NULL DEFAULT 0 COMMENT '0为TEMP(临时),1为USED(使用中)',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '修改时间',
    PRIMARY KEY (`id`),
    KEY `idx_status_time` (`status`, `create_time`) COMMENT '用于定时清理临时图片',
    KEY `idx_post_id` (`post_id`) COMMENT '用于按帖子找图片时'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='帖子图片表-区分临时和正在帖子中使用的图片';
```

**设计说明：**
- 配合 MinIO 对象存储使用
- `post_id` 允许 NULL：用户编辑帖子时先上传图片（TEMP），发布/保存帖子后再绑定 post_id 并标记为 USED
- `status` 状态流转：0(TEMP) → 1(USED)。可设置定时任务清理长时间未绑定的 TEMP 图片
- `object_name` 存储 MinIO 中的对象路径，便于删除时直接操作 MinIO
- 无外键约束，应用层控制关联关系

```sql
    CONSTRAINT `fk_history_users` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE,
    CONSTRAINT `fk_history_posts` FOREIGN KEY (`post_id`) REFERENCES `posts` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='浏览历史表';
```

**优化建议：**
- 定期清理旧数据（只保留最近3个月）
- 可以考虑用Redis存储，定期同步到MySQL

## 🔗 表关系图

```
users (用户表)
  ├─ 1:N ─> posts (发布帖子)
  ├─ 1:N ─> comments (发表评论)
  ├─ M:N ─> posts (点赞, 通过likes表 target_type=1)
  ├─ M:N ─> posts (收藏, 通过collects表)
  ├─ M:N ─> comments (点赞评论, 通过likes表 target_type=2)
  ├─ M:N ─> users (关注, 通过follows表)
  ├─ 1:N ─> notifications (接收通知) [待建]
  └─ 1:N ─> browsing_history (浏览历史) [待建]

posts (帖子表)
  ├─ N:1 ─> users (作者，应用层关联)
  ├─ N:1 ─> categories (所属分区，应用层关联 + category_name冗余)
  ├─ 1:N ─> comments (包含评论)
  └─ 1:N ─> post_images (帖子图片，应用层关联)

comments (评论表)
  ├─ N:1 ─> posts (所属帖子，应用层关联)
  ├─ N:1 ─> users (评论者，应用层关联)
  └─ 1:N ─> comments (楼中楼回复, self-join，应用层关联)

categories (分区表)
  └─ 1:N ─> posts (包含帖子)

  └─ N:1 ─> posts (所属帖子，应用层关联)
```

## 📈 索引优化建议

### 常用查询场景的索引

1. **查询用户的所有帖子（按时间降序）**
```sql
-- 使用索引: idx_user_id, idx_create_time
SELECT * FROM posts WHERE user_id = ? ORDER BY create_time DESC;
```

2. **查询热门帖子（按点赞数）**
```sql
-- 使用组合索引: idx_hot
SELECT * FROM posts 
WHERE status = 2 
ORDER BY like_count DESC, comment_count DESC 
LIMIT 20;
```

3. **查询某个分区的帖子**
```sql
-- 使用索引: idx_category_id, idx_create_time
SELECT * FROM posts 
WHERE category_id = ? AND status = 2 
ORDER BY create_time DESC;
```

4. **查询某个帖子的评论（分页）**
```sql
-- 使用组合索引: idx_post_time(post_id, create_time)
SELECT * FROM comments 
WHERE post_id = ? AND is_deleted = 0 
ORDER BY create_time DESC
LIMIT 20 OFFSET 0;
```

5. **查询启用的分区（按权重排序）**
```sql
-- 使用组合索引: idx_active_sort(is_active, sort_order)
SELECT * FROM categories 
WHERE is_active = 1 
ORDER BY sort_order DESC;
```

6. **清理临时图片（定时任务）**
```sql
-- 使用组合索引: idx_status_time(status, create_time)
SELECT * FROM post_images 
WHERE status = 0 AND create_time < DATE_SUB(NOW(), INTERVAL 24 HOUR);
```
