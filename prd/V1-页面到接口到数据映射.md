# V1 页面 → 接口 → 数据 映射（桥梁文档）

> 目的：把“原型/页面设计”落到“接口与数据库”，避免你在改表时失控。
>
> 原则：V1 只做“必须项”，其余写成 V1.1。

---

## 0. 全局约定

### 0.1 主要实体

- 用户：`users`
- 分区：`categories`（V1 仅一级分区）
- 帖子：`posts`
- 评论：`comments`
- 标签：`tags`、`post_tags`（V1 新增）

### 0.2 帖子状态

- 草稿：DRAFT
- 待审核：PENDING_REVIEW
- 已发布：PUBLISHED
- 已拒绝：REJECTED
- 已删除：DELETED

### 0.3 审核开关

- `review.enabled`（全局）

### 0.4 首页排序字段

- 推荐新增：`posts.last_activity_time`
- V1 可直接在“新增评论成功后”更新该字段（并发写入优化放 V1.5）

## 1. 首页（/）

### 1.1 页面要展示的数据（DTO/VO）

列表每条卡片：

- `postId`
- `title`
- `categoryId`
- `categoryName`
- `summary`（最多 300 字）
- `authorId`
- `authorName`
- `authorAvatarUrl`（可选）
- `lastActivityTime`
- `viewCount`
- `commentCount`
- `tagList`（可选：V1 可先不展示，或展示前 3 个）

侧边栏：

- 主分区列表（仅启用）
- 热门标签列表（可选，V1 可做静态或按 use_count）

### 1.2 页面需要的接口

- `GET /api/posts`：分页获取“已发布”帖子列表（默认按活跃度排序）
- `GET /api/categories`：获取启用分区
- `GET /api/tags/hot`（可选）：热门标签

### 1.3 接口背后的数据库读写

#### `GET /api/posts`

建议 SQL 条件：

- `status = PUBLISHED`
- 可选筛选：`categoryId`、`tagId`
- 排序：`last_activity_time DESC`

需要 join：

- `users`（拿作者名/头像）

标签展示（两种做法）：

- V1 简化：不在列表返回 tagList
- V1 完整：先分页拿 postIds，再批量查 post_tags + tags 组装

## 2. 发帖页（/create-post）

### 2.1 页面要展示的数据

创建模式：

- 分区下拉列表
- 标签选择（输入 + 推荐）

编辑模式：

- 帖子详情（作者可见草稿/被拒/待审核）
- 当前状态提示
- 已拒绝时显示拒绝原因（从审核日志或 posts 字段）

### 2.2 页面需要的接口

- `GET /api/categories`：分区列表
- `GET /api/tags/suggest?q=xxx`：标签建议（可选，V1.1）

核心动作（推荐动作语义）：

- `POST /api/posts`：创建草稿（返回 postId）
- `PATCH /api/posts/{id}`：更新草稿（自动保存/手动保存共用）
- `POST /api/posts/{id}/publish`：发布动作（后端决定进入 PENDING_REVIEW 或 PUBLISHED）

标签绑定：

- 方案 A（推荐）：在 `PATCH /api/posts/{id}` 中带 `tagIds` 或 `tagNames` 更新
- 方案 B：独立接口 `PUT /api/posts/{id}/tags`

### 2.3 数据库写入点

- 草稿创建：写 `posts`（status=DRAFT）
- 草稿更新：更新 `posts.title/summary/content/category_id/cover_image/update_time` 等
- 发布动作：更新 `posts.status`（根据开关）
- 标签：维护 `post_tags`（先删后插 or 差量更新）

## 3. 帖子详情页（/posts/:id）

### 3.1 页面要展示的数据

- 标题、分区、标签
- 作者信息（昵称/头像/技术标签）
- 浏览量、评论数
- 正文
- 评论列表
- 状态条（仅作者/管理员可见）
  - 待审核：提示“审核中”
  - 已拒绝：展示拒绝原因

### 3.2 页面需要的接口

- `GET /api/posts/{id}`：获取帖子详情（包含权限控制）
- `GET /api/comments/{postId}/comments?page=&size=`：评论列表
- `PUT /api/comments/{postId}/comments`：发表评论

可选：

- `POST /api/posts/{id}/views`：浏览量上报（V1 可先不做独立接口，直接在 GET 里 +1 也可）

### 3.3 数据库读写

- `GET /api/posts/{id}`：读取 posts + users + tags
- 评论创建：写 comments，同时更新 posts.comment_count，并更新 posts.last_activity_time

## 4. 个人中心（/me）

### 4.1 页面结构

- 个人资料
- 我的帖子（按状态 Tab）
- 我的足迹（仅浏览历史）

### 4.2 页面需要的接口

个人资料：

- `GET /api/users/me`（建议新增）
- `PATCH /api/users/me`（建议新增，更新简介/地区/技术标签等）
- `POST /api/auth/upload/userAvatar`（已有）

我的帖子：

- `GET /api/posts/user/{userId}?status=xxx&page=&size=`（可用现有接口扩展 status 参数）

已发布申请精选：

- `POST /api/posts/{id}/feature-request`（建议新增）

我的足迹：

- `GET /api/me/history?page=&size=`（V1.1）

### 4.3 数据库读写

- 个人资料：读/写 users
- 我的帖子：按 userId + status 查询 posts
- 精选申请：写“精选申请记录”或写 posts.is_featured_request（两种实现选其一）

## 5. 作者公开主页（/users/:id）

### 5.1 页面要展示的数据

- 头像、昵称、简介
- 技术标签（徽章）
- 已发布帖子列表（只展示 PUBLISHED）

### 5.2 页面需要的接口

- `GET /api/users/{id}/public`（建议新增）
- `GET /api/posts/user/{userId}`：只返回已发布（普通访客视角）

### 5.3 数据库读写

- 用户公开信息：读 users
- 用户帖子列表：按 userId + status=PUBLISHED 查询 posts

## 6. 管理后台（/admin）（V1 最小集）

### 6.1 页面模块

- 待审核帖子列表
- 精选申请列表
- 分区管理

### 6.2 页面需要的接口

待审核帖子：

- `GET /api/admin/posts?status=PENDING_REVIEW&page=&size=`（建议新增或扩展）
- `POST /api/admin/posts/{id}/approve`（建议新增）
- `POST /api/admin/posts/{id}/reject`（建议新增，reason 必填）

精选申请：

- `GET /api/admin/feature-requests?page=&size=`（建议新增）
- `POST /api/admin/feature-requests/{id}/approve`（建议新增）
- `POST /api/admin/feature-requests/{id}/reject`（建议新增）

分区管理：

- 已有管理员分区接口（分页/详情/创建/启停/排序/删除）

### 6.3 数据库读写建议（解耦审核）

为了降低 Post 与审核耦合，建议新增：

- `post_moderation_log`：记录审核/精选/删除等治理动作与原因（事实来源）

并让 `posts.status` 仅表示“当前状态”。
