## Codebase Patterns
- 项目使用 MyBatis + `@Mapper` 注解，简单查询用 `@Select`/`@Insert` 注解，复杂动态 SQL 用 XML 映射文件（`resources/mapper/`）
- 实体类位于 `POJO/entity/`，DTO 位于 `POJO/dto/`，VO 位于 `POJO/vo/`
- 统一结果类 `Result<T>` 返回，错误使用 `ErrorCode` 枚举 + `BusinessException`
- 枚举定义位于 `common/enums/`
- 服务接口在 `service/`，实现在 `service/impl/`
- 测试使用 `@ExtendWith(MockitoExtension.class)` + `@Mock` + `@InjectMocks` 模式
- `community-backgroundend/.gitignore` 忽略 `*.sql`，新增 SQL 文件需 `git add -f`
- Redis 配置在 `RedisConfig.java`，使用 `StringRedisSerializer` + `GenericJackson2JsonRedisSerializer`
- 权限控制使用 `@PreAuthorize("hasRole('ADMIN')")` 注解
- PostStatus 枚举定义帖子状态：0=DRAFT, 1=PENDING_REVIEW, 2=PUBLISHED, 3=REJECTED, 4=DELETED, 5=SHADOW_BANNED
- 审核决策阈值通过 `moderation_threshold_config` 表配置，key: `auto_approve_max`（默认30）, `auto_reject_min`（默认70）
- `ModerationDecisionService.decide(text, user, targetId, targetType)` 是审核决策入口，返回 `ModerationDecisionResult`
- 灰区内容自动写入 `moderation_queue` 审核队列表
- `ModerationDecision` 枚举: AUTO_APPROVE→status=2, PENDING_REVIEW→status=1, AUTO_REJECT→status=3
- SHADOW_BANNED(status=5) 仅由管理员人工审核手动触发，不纳入自动决策
- CompressTest 和 PostServiceImplTest 存在 pre-existing 测试失败（环境/mock问题），非审核模块引入
- SQL 初始化脚本在 `sql/springboot_db.sql`，Docker Compose 通过挂载 `sql/` 自动执行
- 用户画像加权采用 `user_risk_factor_config` 配置表，支持灵活的因子名+运算符+阈值+系数配置
- 多因子命中时取最大加权系数（MAX策略），避免极端叠加
- User 实体已增加 `violationCount` 字段，对应 users 表 `violation_count` 列
- `RiskScoringService.evaluateWithUserProfile(text, user)` 是带用户画像加权的评分入口
- 帖子可见性控制已在 `PostServiceImpl` 和 `PostMapper.xml` 中实现：列表查询默认按 PUBLISHED 过滤，作者视角排除 DELETED，管理员视角不过滤
- `BusinessException` 使用 `getCode()` (String) 而非 `getErrorCode()`，测试中用 `ErrorCode.XXX.getCode()` 比较
- SHADOW_BANNED 帖子的评论可见性需在 `CommentServiceImpl.findByPostIdByPage` 中控制
